  ПРЕДСЕДАТЕЛЬ КОЛХОЗА — ЯДРО СИМУЛЯЦИИ

Статическая библиотека core на C++20. Вся симуляция и логика игры.
Ядро не знает про Unreal Engine и собирается там, где движка нет вообще.

Документация ядра   — manual/README.md
Правила разработки  — CLAUDE.md
Дизайн игры         — ../manual/README.md


--------------------------------------------------------------------------------
  СТРУКТУРА ПРОЕКТА
--------------------------------------------------------------------------------

  include/       Общие заголовки всех модулей. То, что модули показывают
                 наружу. Внутренние заголовки лежат рядом со своим .cpp.

  subprojects/   Статические библиотеки проекта — модули ядра. Папка на
                 модуль, все они складываются в одну библиотеку core.

  src/           Исполняемый файл игры, main.cpp. Вторая фаза: сейчас пусто,
                 сборка включается ключом -DKOLKHOZ_BUILD_GAME=ON.

  tests/         Консольные приложения: тесты подсистем и прогоны симуляции,
                 числа которых сверяются с manual/balance/49-simulations.md.

  depends/       Сторонние библиотеки в исходниках (enkiTS, ReaderWriterQueue,
                 ImGui). Собираются со своими настройками, не с нашими.

  libs/          Сторонние библиотеки в виде готовых .a и .lib.

  scripts/       Вспомогательные скрипты: сборка на Windows-хосте, git-хуки.

  manual/        Техническая документация ядра.

  build/         Результат сборки. В git не попадает, удаляется свободно.


--------------------------------------------------------------------------------
  СБОРКА
--------------------------------------------------------------------------------

Система сборки — CMake плюс Ninja, компилятор Clang. Makefile ничего не
собирает сам, он только избавляет от запоминания команд.

  make build          собрать Debug, настроив при необходимости
  make release        собрать Release
  make rebuild        собрать с нуля
  make test           прогнать тесты через ctest
  make asan           сборка с санитайзерами address и undefined
  make clean          убрать объектные файлы, конфигурацию оставить
  make distclean      удалить каталог сборки целиком
  make info           что установлено и какие настройки действуют
  make help           весь список

Ядро собирается за секунды — сборка с нуля ничего не стоит.

ВАЖНО: изменил заголовок с данными (структуру, перечисление) — собери с нуля.
Инкрементальная сборка может собрать не всё, и получится битая библиотека без
единой ошибки компиляции. Странное поведение — первым делом make rebuild.

Напрямую, без Makefile:

  cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
  cmake --build build

Ключи настройки:

  -DKOLKHOZ_BUILD_TESTS=ON|OFF     собирать содержимое tests/     (по умолчанию ON)
  -DKOLKHOZ_BUILD_GAME=ON|OFF      собирать src/                  (по умолчанию OFF)
  -DKOLKHOZ_WERROR=ON|OFF          предупреждения как ошибки      (по умолчанию ON)
  -DKOLKHOZ_SANITIZERS="address;undefined"


--------------------------------------------------------------------------------
  СБОРКА ПОД MSVC НА WINDOWS-ХОСТЕ
--------------------------------------------------------------------------------

Нужна, когда меняется библиотека для UE: ядро должно собираться обоими
компиляторами, расхождения ловятся сразу.

  make sync           отправить исходники на хост
  make win            отправить, собрать и опубликовать (Debug)
  make win-release    то же, Release — эту библиотеку берёт слой графики
  make win-clean      снести каталог сборки Debug на хосте и собрать заново
  make win-setup      порядок первичной настройки и публичный ключ виртуалки

Перенос идёт rsync с ключом --checksum: сравнение по содержимому, а не по
времени файлов — отметки времени между виртуалкой и хостом разъезжаются.

Исходники живут на хосте в C:\MyGames\Kolkhoz\core-msvc, сборка — в build-msvc
внутри него. У каждой конфигурации свой каталог сборки, а результат кладётся
в publish/<конфигурация>/ — include, lib/core.lib и VERSION рядом с ней; это и
есть то, что забирает потребитель, каталог сборки смотреть не надо. Обратно на
виртуалку библиотека приезжает в artifacts/<конфигурация>/core.lib.
Публикуемая core.lib содержит внутри enkiTS: сама по себе она не линкуется.
Другой хост или каталог — make win WIN_HOST=... WIN_DIR=...

Первичная настройка хоста делается скриптом scripts/win-setup.ps1: OpenSSH,
MSYS2 с rsync, Build Tools, ключ, брандмауэр. Порядок и подвохи — в
manual/setup/60-windows-host.md.


--------------------------------------------------------------------------------
  ВЕРСИИ
--------------------------------------------------------------------------------

Два номера, и они независимы:

  VERSION        версия библиотеки ядра, major.minor.patch
  VERSION_SAVE   версия двоичного формата сохранения, целое число

Формат сохранения переживает много выпусков библиотеки, поэтому номера разные.
Правится файл; заголовок core_common/version.h генерируется при настройке, и
править его копию в build/ бессмысленно.

  make version      показать оба номера
  make bump-patch   поднять версию: сдан модуль
  make bump-minor   поднять версию: сдан этап плана
  make bump-major   поднять версию: сломалась граница с UE

ВЕРСИЯ ПОДНИМАЕТСЯ ПРИ ЗАКРЫТИИ ЦИКЛА СДАЧИ. Это делает /check_static_new сам,
одним коммитом со сдаваемой работой: patch — сдан модуль, minor — сдан этап
плана. Досрочно остановленный цикл версию не трогает.

major поднимает человек — это сломанная граница с UE. VERSION_SAVE тоже человек:
его подъём означает, что чьи-то сохранения перестали открываться, и об этом надо
сказать вслух.

ВЕРСИЯ ИГРЫ СЮДА НЕ ОТНОСИТСЯ. Игры пока нет, её версия будет своя, на стороне
UE, по своей шкале.

Правила целиком — manual/setup/57-versioning.md.


--------------------------------------------------------------------------------
  КАЧЕСТВО КОДА
--------------------------------------------------------------------------------

  make format         применить .clang-format ко всем исходникам
  make format-check   проверить форматирование, ничего не меняя
  make tidy           статический анализ clang-tidy
  make docs           выжимка Doxygen в build/doc

Форматирование применяется автоматически при коммите. Включить один раз:

  make hooks

Хук зовёт clang-format для файлов, попавших в коммит, и добавляет правки
обратно. Если clang-format не установлен, хук молча пропускает работу.

--------------------------------------------------------------------------------
  ЖЕЛЕЗНЫЕ ПРАВИЛА
--------------------------------------------------------------------------------

  1. Ядро не знает про Unreal. Ни одного заголовка движка, ни одного типа.
     Проверка — библиотека собирается там, где Unreal не установлен.

  2. Детерминизм. Одинаковый вход даёт одинаковый выход всегда. Результат в
     один поток обязан совпадать с результатом в много потоков.

  3. Стандарт C++20, не 23: движок не поддерживает.

  4. Модули не тянутся друг к другу напрямую. Потянулись — граница проведена
     неправильно, об этом надо сказать, а не добавлять зависимость.

Полностью — CLAUDE.md.
