# Председатель колхоза — План первой фазы

> Составлен 23 августа 2026. Архитектура — `50-architecture.md`.

---

## 1. Цель фазы

**Работающее ядро симуляции, проверенное прогонами. Без графики вообще.**

| Что должно получиться | |
|---|---|
| **Библиотека ядра** | Собирается на Linux и Windows |
| **Прогон симуляции** | Консольный, с ImGui |
| **Десять лет за минуты** | Воспроизводимо |
| **Числа сходятся с расчётами** | (`49-simulations.md`) |
| Инфраструктура | Сборка, связь машин, инструменты |

**Чего в первой фазе не будет: UE, графики, интерфейса игры, звука, контента.**

---

### Почему без UE

| Довод | |
|---|---|
| **Ядро — это и есть игра** | Графика показывает то, что оно считает (`50-architecture.md` §6) |
| **Проверить можно без картинки** | Прогонами, как уже делали |
| **Экономит месяцы** | Не отвлекаемся на движок, пока нечего показывать |
| **Ошибки дешевле** | Правка ядра — секунды сборки |
| Риск | **Если баланс не сойдётся, графика была бы выброшена** |

**Сначала убедиться, что игра работает как система. Потом показывать.**

## 2. Этап 0: Инфраструктура

**Делается первым, занимает дни.**

| Задача | Проверка готовности | Модель |
|---|---|---|
| **Репозиторий и структура папок** | Плоская, не глубже трёх уровней (`50-architecture.md` §7д) | Обычная |
| **CMake плюс Ninja** | Собирается в виртуалке | Обычная |
| **`.clang-format`, `.clang-tidy`** | Применяются автоматически | Обычная |
| **Doxygen настроен** | Генерирует выжимку по интерфейсам | Обычная |
| **Виртуалка AlmaLinux 10** | **6–8 ГБ памяти, 40 ГБ диска, без графики**, сеть bridged | Обычная |
| **Проверить AVX2 в госте** | `lscpu \| grep avx2` — VirtualBox должен пробросить. **Ryzen 5800X поддерживает** | Обычная |
| **EPEL и CRB подключены** | Оттуда Ninja и ccache | Обычная |
| **Снимок после настройки** | Откат бесплатен | Обычная |
| **OpenSSH Server на хосте** | `ssh win "echo ok"` работает из виртуалки | Обычная |
| **Скрипты-обёртки MSVC** | `ssh win "build-core.bat"` собирает | Обычная |
| **Раскладка** | Ядро в виртуалке, проект UE на хосте | Обычная |
| **`rsync --checksum` для переноса** | Синхронизация перед MSVC-сборкой | Обычная |
| **ccache** | Кеш по содержимому работает | Обычная |
| Каркас тестов | Запускается одной командой | Обычная |

**Весь этап — обычная модель.** Настройка инструментов, ошибки видны сразу.

**Критерий этапа: пустая библиотека собирается в виртуалке и под MSVC, обе — одной командой из виртуалки.**

**Места на диске нужно немного:** виртуалка и **Build Tools for Visual Studio** — около 60–70 ГБ. **Ни Unreal, ни полная Visual Studio до второй фазы не нужны** (`50-architecture.md` §7г). Версия движка на вторую фазу — **UE 5.8**.

## 3. Этап 1: Скелет ядра

**Каркас, в который дальше вставляются системы.**

| Задача | Что входит | Модель |
|---|---|---|
| **Модель состояния и раскладка данных** | Что где лежит, кто читает | **Старшая** |
| **Цикл симуляции с фазами** | Порядок фаз, барьеры (`50-architecture.md` §7е) | **Старшая** |
| **Двойная буферизация состояния** | Читаем прошлое, пишем новое | **Старшая** |
| **Интерфейсы подсистем** | Контракты на всю разработку | **Старшая** |
| Базовые типы и структуры | Идентификаторы, координаты, время | Обычная |
| Планировщик задач | enkiTS, параллельный проход по массивам | Обычная |
| Режим одного потока | Обязательно, для проверки детерминизма | Обычная |
| **Формат таблиц** | CSV или JSON — решение на весь проект | **Старшая** |
| **Разметка модулей на цели CMake** | Границы зависимостей (`50-architecture.md` §7д) | **Старшая** |
| Чтение таблиц, реализация | | Обычная |
| Логирование | Простое, в файл и в консоль | Обычная |

**Самый важный этап для старшей модели.** Здесь закладывается всё, что потом дорого менять: раскладка состояния, порядок фаз, границы подсистем.

**Критерий: пустой мир тикает 10 000 шагов, результат одинаков в один и в много потоков.**

## 4. Этап 2: Время и календарь

**Первая настоящая система, от неё зависят все.**

| Задача | Ссылка | Модель |
|---|---|---|
| **Шаг симуляции, сутки, месяцы, сезоны, годы** | `02-gameplay-mechanics.md` §3 | Обычная |

## 5. Этап 3: Жители

**Ядро всей игры.**

| Задача | Ссылка | Модель |
|---|---|---|
| **Структура данных жителя** | Девять метрик плюс склонности — **раскладка на всю игру** | **Старшая** |
| **Взаимовлияние метрик** | Что на что действует и с какими весами | **Старшая** |
| Метрики состояния | Сытость, здоровье, усталость, холод, настроение (`07-metrics.md` §1а) | Обычная |
| Склонности | Интеллект, выносливость, спортивность, оптимизм, идейность | Обычная |
| Возраст и старение | С ускорением ×4 (`52-demography.md`) | Обычная |
| Семьи и дворы | Состав, связи | Обычная |
| **Демография** | Рождения, смерти, миграция. **Нелинейная, влияет на всё** | **Старшая** |
| Общественный статус | Пионер, комсомолец, партийный (`22-village-council-and-organizations.md` §4) | Обычная |

**Старшая — на проектирование, обычная на реализацию.** Житель — центральная сущность, ошибка в раскладке отзовётся везде.

**Критерий: население растёт по кривой из расчётов — 200 к 7 году, 500 к 14, 1500 к 33.**

## 9. Этап 7: Прогон и сверка

**Главная проверка фазы.**

| Задача | | Модель |
|---|---|---|
| Приложение прогона на ImGui | Ползунки, графики, таблицы | Обычная |
| Прогон на 30 лет за минуты | Без графики | Обычная |
| **Сверка с расчётами и разбор расхождений** | **Почему не сошлось** (`49-simulations.md`) | **Старшая** |
| **Отладка недетерминизма**, если всплывёт | Один поток против многих | **Старшая** |
| **Подбор параметров баланса** | `13-polish-backlog.md` | **Старшая** |
| Сохранение и загрузка | Продолжается так же | Обычная |
| Правка таблиц и повторный прогон | Цикл в секунды | Обычная |

**Этап балансировщика.** Здесь старшая модель нужна больше всего после первого этапа.

**Критерий фазы целиком: числа сходятся с ручными расчётами в пределах разумного, и расхождения объяснимы.**

## 9а. Сводка по моделям

**Правило: проектирование и диагностика — старшая, реализация и рутина — обычная** (`54-agents.md` §9а).

| Этап | Доля старшей |
|---|---|
| 0. Инфраструктура | **Нет** |
| **1. Скелет ядра** | **Высокая:** раскладка состояния, фазы, интерфейсы |
| 2. Время | Нет |
| **3. Жители** | **Средняя:** структура данных и демография |
| 4. Земля | Низкая: только плодородие |
| 5. Труд | Низкая: только назначение |
| 6. Питание и ЛПХ | Низкая: только время на ЛПХ |
| **7. Прогон и сверка** | **Высокая:** разбор расхождений и баланс |

**Максимум приходится на первый и последний этапы.** В середине — почти вся обычная.

**На Max это укладывается в лимит:** старшая модель нужна на четверти работы, а доступно до половины недельного лимита.

## 11. Чего не делаем в первой фазе

**Список важнее плана: он защищает от расползания.**

| Не делаем | Когда |
|---|---|
| **Ничего в UE** | Вторая фаза |
| **Графика, камера, интерфейс игры** | Вторая фаза |
| **Звук и музыка** | Позже |
| **Логистику и транспорт** | Вторая фаза: она не влияет на баланс сильно (`49-simulations.md`) |
| **Строительство и износ** | Вторая фаза |
| **Диалоги, события, ролевые линии** | Третья фаза |
| **Скрипты и Lua** | Третья фаза |
| **Криминал, теневое производство** | Третья фаза |
| Район, лимиты, репутация | **Упрощённо:** план сдачи как число, без механики |

**Всё, что не влияет на главный вопрос «сходится ли баланс», откладывается.**

## 11а. Заглушки — это нормально

**Дизайн не закончен и будет меняться** (`50-architecture.md` §7ж).

| Правило | |
|---|---|
| **Отсутствующая система — не отсутствующий интерфейс** | Интерфейс есть, тело пустое |
| **Заглушка помечена `STUB`** | Находится поиском |
| **Возвращает нейтральное значение** | Вызывающий код работает |
| Список заглушек ведётся | Отдельным файлом |

**Что закладывается заглушками уже в первой фазе:**

| Система | Заглушка |
|---|---|
| **Логистика** | Доставка мгновенная |
| **Строительство** | Юнит появляется сразу |
| **Износ** | Не растёт |
| **Криминал** | Давление ноль |
| **Район и лимиты** | План — просто число |
| Диалоги и события | Ничего не происходит |

**Во второй фазе заполняются тела, а не переписываются вызовы.**

## 12. Риски фазы

| Риск | Что делать |
|---|---|
| **Баланс не сойдётся** | **Это и есть цель фазы — узнать.** Лучше сейчас, чем после графики |
| **Детерминизм сломается** | Режим одного потока ловит сразу (`50-architecture.md` §7е) |
| **Ядро окажется медленным** | Профилировать рано, оптимизировать по факту |
| **Расползание в UE** | Список §11 — отказывать себе явно |
| Слишком детальная симуляция | **Резать.** Что не даёт решений — не моделируем (`02-gameplay-mechanics.md` §0) |
| **Дизайн изменится по ходу** | **Ожидаемо.** Интерфейсы с запасом, заглушки (§11а) |

## 13. Что даёт завершение фазы

| Результат | |

**После первой фазы можно честно ответить, стоит ли делать эту игру.**

## 13а. Кто это делает

**Одного агента достаточно** (`54-agents.md` §3).

| Роль | Когда |
|---|---|
| **Разработчик ядра** | Всю фазу, **один** |
| **Балансировщик** | С этапа 5, второй агент |

**Почему не больше:** этапы идут последовательно, интерфейсы ещё проектируются, подсистемы связаны данными. **Параллелить, пока границы не проведены, — только терять время.**
