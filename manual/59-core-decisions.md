# Решения, которые принимает ядро

> Общий реестр решений проекта — [Реестр решений](../../manual/process/09-open-questions.md),
> он корневой.
> **Здесь только то, что решает ядро само.**

**Зачем отдельный список.** В [Архитектуре §8](../../manual/technical/50-architecture.md#8-что-решено-и-что-нет) есть строки «не решено», которые
касаются исключительно ядра. Ходить с ними в корневой проект незачем: ответ всё равно
даёт тот, кто пишет ядро. Список нужен, чтобы следующая сессия не тратила проход на
выяснение, чьё это решение.

## 2. Закрытые ядром

| Решение | Что выбрано | Где записано |
|---|---|---|
| **Модель состояния** | Состояние — данные в `core_common`, модули — логика; таблицы `StateTable`, id не переиспользуются; **массы — целые граммы**, метрики — float 0–100 | [`52-state-model.md`](52-state-model.md) |
| **Цикл шага** | **Тик — один игровой час** (24 в сутках); семь фаз с барьерами, копия в начале шага, обмен в конце; слоты фаз типизированы, заглушка вместо пустого слота | [`53-step-cycle.md`](53-step-cycle.md) |
| **Модули** | Три яруса: инфраструктура / предметные / сборка; предметные друг о друге не знают, параллельный слот — ровно у одного модуля, составные слоты 3 и 7 — у `core_world` | [`54-modules.md`](54-modules.md) |
| **Интерфейсы подсистем** | Один на подсистему: фазы — ссылкой, под-шаги слота решений — именованные методы, создание — фабрики; **подсистемы не хранят состояние мира**, порядок в слоте 3 — назначения → демография → номенклатура | [`54-modules.md` §3](54-modules.md#3-слоты-фаз-кто-владеет) |
| **Модель людей** | Раскладка жителя и семьи на всю игру: хранится неведомое, производные считаются; день рождения знаковый, возраст через `life_speedup`; демография — посуточные ставки эталона, довольство — веса эпох | [`63-people-model.md`](63-people-model.md) |
| **Модель земли** | Шкала плодородия 0–100 с нейтралью 50 (множитель = плодородие÷50); один обобщённый юнит с колонками вместимости; мгновенные переходы фаз поля до прихода труда | [`64-land-model.md`](64-land-model.md) |
| **Модель труда** | Труд целиком последовательный (первый подшаг слота решений); швы с производством через состояние (`work_days_remaining`, `care_days_remaining`); нормы в таблицах реальные, ÷7 при чтении; эффективность — отклонения от эталонного работника | [`65-labor-model.md`](65-labor-model.md) |
| **Модель питания и ЛПХ** | Кладовая семьи — тот же `ResourceAmounts`, что склад; нормы еды в зерновом эквиваленте **на игровой год** (÷48, без ÷7); семья ест пропорционально запасам; отдача огорода = часы÷4; стада — когорты с дробными потоками, возрасты биологические, ставки годовые | [`66-food-model.md`](66-food-model.md) |
| **Формат сохранений** | **Двоичный, поле за полем, `float` битами**; словари ключей четырёх таблиц определений впереди, `DefId` и плотные векторы перепривязываются по ключам; **несовпадение `VERSION_SAVE` — отказ, не миграция**; модуль `core_save`, два слоя API — байты и файлы | [`67-save-format.md`](67-save-format.md) |
| **Модель возраста стада** | **Риск смерти интегрируется по возрастам, которые в стаде есть, а не берётся в средней точке; хоронят с верхнего края, разброс сужается вместе со стадом.** Строка по-прежнему хранит одно число — сумму возрастов. Средняя точка была неверна в обе стороны и вдобавок неустойчива: мёртвых списывали тоже по среднему, среднее не опускалось никогда, и любое стадо без приплода скатывалось в ноль | [`66-food-model.md` §6](66-food-model.md#6-стада-приплод-возраст-продукция-корм) |
| **Луг — угодье, а не культура** | `FieldRow::kind` (`LandKind`) в один байт: у луга нет севооборота, сева, семян, навоза, плодородия и погодного стресса; урожайность — канонная ставка за сезон, один укос в год. Прежде луга были полями тимофеевки и поднимали себе плодородие с 55 до 100 | [`64-land-model.md` §2а](64-land-model.md#2а-луг--не-культура) |
| **Ведомость прогона** | **Потоки года — блок `WorldState::ledger`**, который пишут последовательные под-шаги в месте потока, а параллельные — свёрткой слота событий по часам; книга закрывается первым тиком нового года; лист — CSV, строка на год, заголовок из таблиц; модуль `core_report` | [`68-run-ledger.md`](68-run-ledger.md) |
| **Формат таблиц баланса** | **CSV**, один диалект на весь конвейер (Sheets → репозиторий → ядро → `DataTable`); колонка `key`, `DefId` = номер строки, неизвестные колонки игнорируются; балансовое — в CSV, структурное — `constexpr` | [`61-balance-tables.md`](61-balance-tables.md) |
| **Система сборки ядра** | **CMake плюс Ninja**, Clang в виртуалке, MSVC на хосте | [`setup/55-project-layout.md`](setup/55-project-layout.md) |
| **Публикация артефакта** | **Публикация — отдельное понятие, а не остаток в каталоге сборки.** Каталог сборки у каждой конфигурации свой; `publish/{Debug,Release}/` — `include`, `lib/core.lib`, `VERSION` рядом с библиотекой; единственный писатель — скрипт ядра, каталог переписывается целиком. **Выкладывается одна библиотека: `enkiTS.lib` слита внутрь**, иначе восемь символов `enki::` остаются неразрешёнными и наш выбор планировщика уезжает в чужой скрипт сборки. Слою графики нужен Release — редактор UE поставляется с `/MD`. Принято 31.08.2026 по посылке `core-publish-release` | [`setup/60-windows-host.md` §6а](setup/60-windows-host.md#6а-публикация-что-именно-забирает-слой-графики) |
| Раскладка каталогов | `include/<модуль>/`, `subprojects/<модуль>/`, `tests/unit/`, `tests/run/` | Там же |
| Версии | `VERSION` и `VERSION_SAVE`, заголовок генерируется | [`setup/57-versioning.md`](setup/57-versioning.md) |
| Порядок сдачи | Unit-тест на модуль, статанализ по дельте | [`setup/56-static-analysis-and-tests.md`](setup/56-static-analysis-and-tests.md) |
| Правила именования | Плюс приставки `I` и `g_` | [Правила ядра §4](../CLAUDE.md#4-стиль-кода) |

> **Строка «Система сборки ядра» из TODO в [Архитектуре §8](../../manual/technical/50-architecture.md#8-что-решено-и-что-нет) снята** — 25.08.2026,
