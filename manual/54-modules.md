# Модули ядра и граф зависимостей

> Задача F3 этапа 1 ([план §3](plan/51-phase1-plan.md#3-этап-1-скелет-ядра)). Цели объявлены в
> `subprojects/*/CMakeLists.txt`; правила сборки — [`setup/55-project-layout.md`](setup/55-project-layout.md).
> Опирается на [модель состояния](52-state-model.md) и [цикл шага](53-step-cycle.md).

---

## 1. Три яруса

```
   ИСПОЛНЯЕМЫЕ            tests/unit, tests/run, src/
        │ линкуют core
   СБОРКА                 core_world — генезис мира, StepPhaseSet, слоты 3 и 7
        │ видит всех
   ПРЕДМЕТНЫЕ             core_time   core_residents   core_production
                          core_logistics   core_labor
        │ только вниз                 ↑ друг о друге НЕ знают
   ИНФРАСТРУКТУРА         core_common   core_log   core_tables   core_sim
                          core_save   core_report   core_boundary  ← листья: их зовут только исполняемые
```

| Правило | |
|---|---|
| **Предметные модули не называют друг друга** | Данные текут через состояние в `core_common` ([модель состояния §1](52-state-model.md#1-главное-решение-состояние--данные-системы--логика)) |
| **Инфраструктуру можно использовать всем** | База, лог, таблицы, движок шага |
| **`core_world` — единственный, кто видит всех** | Точка сборки; от него не зависит никто, кроме исполняемых |
| **Потянулись два предметных друг к другу — граница неверна** | Сказать, не добавлять зависимость |

## 2. Модули поимённо

| Модуль | За что отвечает | Наполняется |
|---|---|---|
| **core_common** | Идентификаторы, единицы, календарная арифметика, геометрия, операции таблиц, ГПСЧ; **состояние мира — данные** | O1 |
| **core_log** | Лог в файл и консоль | O4 |
| **core_tables** | Загрузка и хранение балансовых таблиц | F5 → O3 |
| **core_sim** | Движок шага: буферы, барьеры, воркеры, режим одного потока | O2 |
| **core_time** | Фаза 1: календарь, сезоны, световой день, погода | Этап 2 |
| **core_residents** | Жители: потребности, питание и ЛПХ, демография, семьи, довольство | Этап 3 (структуру данных жителя проектирует Старшая) |
| **core_production** | Земля и производство: поля, плодородие, циклы юнитов, буферы, стада | Этап 4 |
| **core_logistics** | Слот логистики. **Заглушка «мгновенная доставка»** до второй фазы проекта | Вторая фаза |
| **core_labor** | Труд: назначения, учётчик, рабочий день, трудодни | Этап 5 |
| **core_world** | Генезис стартового поселения, сборка фаз, составные слоты 3 и 7 | По мере этапов |
| **core_save** | Формат сохранений: `WorldState` в байты и обратно, перепривязка `DefId` по ключам ([`67-save-format.md`](67-save-format.md)) | Этап 7: Ф1 → O1 |
| **core_report** | Ведомость прогона: `WorldState::ledger` и состояние на повороте года в CSV ([`68-run-ledger.md`](68-run-ledger.md)) | Этап 7: Ф2 → O2 |
| **core_boundary** | Граница ядра и графики: сессия над собранной симуляцией — время, чтение, распоряжения, события, журнал ([`70-boundary.md`](70-boundary.md)) | Вторая фаза: А1 (контракт принят 31.08.2026), O2 (реализация) |

`core_save`, `core_report` и `core_boundary` — **листья инфраструктурного яруса**: зависят от
`core_common`, `core_tables` (и `core_sim` у границы), подсистем не называют, и от них не зависит
никто внутри ядра — только исполняемые и сторона UE.

**Будущие модули, не создаются сейчас:** `core_events` (третья фаза проекта; до неё слот 7 —
заглушка в `core_world`).

## 3. Слоты фаз: кто владеет

**Каждый параллельный слот принадлежит ровно одному модулю.** Однопоточные составные слоты —
у точки сборки, которая в жёстком порядке зовёт профильные интерфейсы модулей.

| Слот | Владелец |
|---|---|
| 1. Время и погода | `core_time` |
| 2. Потребности (по семьям) | `core_residents` |
| **3. Решения** | **`core_world`**: учётчик из labor → демография из residents → номенклатура из production |
| 4. Производство (по юнитам и полям) | `core_production` |
| 5. Логистика | `core_logistics` (заглушка) |
| 6. Метрики (по семьям) | `core_residents` |
| **7. События** | **`core_world`** (заглушка до `core_events`; с этапа 7 здесь же свёртка и ротация ведомости — [`68-run-ledger.md` §3](68-run-ledger.md#3-кто-что-пишет)) |

Отсюда и зависимость: владельцы слотов держат `core_sim` в PUBLIC — их граница и есть
интерфейс слота. `core_labor` слотом не владеет и `core_sim` не знает.

### Интерфейсы подсистем (задача F4)

**Один интерфейс на подсистему.** Владельцы слотов отдают реализации фаз ссылкой, участники
слота решений — именованные под-шаги; создание — через фабрику. **Подсистемы не хранят
состояние мира** — только конфигурацию; всё изменяемое живёт в `WorldState`, поэтому
`ResetWorld` не требует ни одного обратного вызова.

| Модуль | Интерфейс | Заголовок |
|---|---|---|
| `core_sim` | `ISimulation`, фабрика `CreateStepEngine` | `include/core_sim/step.h` |
| `core_time` | `ITimeSystem` | `include/core_time/time_system.h` |
| `core_residents` | `IResidentsSystem`: две фазы + `RunDemographyDecisions` | `include/core_residents/residents_system.h` |
| `core_production` | `IProductionSystem`: фаза + `RunProductionDecisions` | `include/core_production/production_system.h` |
| `core_logistics` | `ILogisticsSystem` (заглушка «мгновенно») | `include/core_logistics/logistics_system.h` |
| `core_labor` | `ILaborSystem`: `RunAssignmentDecisions` | `include/core_labor/labor_system.h` |
| `core_world` | Фабрики `CreateStartWorld`, `CreateStandardSimulation` | `include/core_world/world.h` |
| `core_boundary` | `ISession`, фабрика `CreateSession`, кодек журнала (А1 — контракт, O2 — реализация) | `include/core_boundary/session.h` |

Под-шаги слота решений зовутся каждый тик; суточную работу реализация сама привязывает к
границе суток. Порядок в слоте 3 закреплён: **назначения → демография → номенклатура** —
расстановка людей происходит до того, как на неё посмотрят остальные.

## 4. Как добавить модуль

1. `subprojects/<имя>/CMakeLists.txt` с `kolkhoz_add_module()` и **явными** зависимостями.
2. Публичные заголовки — `include/<имя>/`, шапка с `@threading`.
3. `tests/unit/<имя>/` — unit-тест обязателен, `make check-tests` напомнит.
4. Строка в таблицу §2 и, если модуль владеет слотом, в §3.

**Пока в модуле нет настоящих исходников, лежит `placeholder.cpp`** — пустая единица
трансляции с одним символом (иначе MSVC ругается на пустой член архива, LNK4221).
Удаляется первым настоящим `.cpp`.

## 5. Чем проверяется граф

| Что | Чем |
|---|---|
| **Явность зависимостей и порядок линковки** | CMake: не объявил — не слинкуется |
| **Дисциплина включений** (`#include "core_x/..."` только по объявленным рёбрам) | `scripts/check_includes.py`, входит в `make check-tests`: сам модуль, прямые рёбра и PUBLIC-замыкание — ровно правило usage requirements CMake |
| Тест на модуль | `make check-tests` |

Путь включений один на всех (`include/`), поэтому сама сборка чужой `#include` не поймает —
за это и отвечает скрипт.
