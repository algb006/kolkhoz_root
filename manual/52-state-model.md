# Модель состояния ядра

> Задача F1 этапа 1 ([план §3](plan/51-phase1-plan.md#3-этап-1-скелет-ядра)). Заголовки — `include/core_common/`:
> `quantities.h`, `ids.h`, `calendar.h`, `geometry.h`, `state_table.h`, `world_state.h`.
> Здесь — решения и карта «что где лежит, кто читает»; подробности каждого типа — в Doxygen
> самих заголовков.

---

## 1. Главное решение: состояние — данные, системы — логика

**Всё состояние мира лежит в `core_common` как простые структуры. Модули-подсистемы владеют
логикой, а не данными.**

| Что | Где |
|---|---|
| **Структуры состояния** | `include/core_common/` — простые агрегаты без методов |
| **Логика подсистем** | Модули `core_time`, `core_residents`, … (границы — задача F3) |
| Кто чем владеет | Модуль **пишет** свои блоки состояния в своей фазе; **читают** все |

**Почему так.** Почти каждая фаза читает чужое состояние: производство читает метрики
работников, метрики читают выдачу со склада, демография читает жильё. Если бы структура
жителя жила в публичном интерфейсе `core_residents`, каждый модуль зависел бы от каждого —
ровно то, что запрещено ([правила ядра §7](../CLAUDE.md#7-структура-сборки)). Состояние в
`core_common` превращает граф зависимостей в звезду: все зависят только от базы.

Интерфейсы подсистем (задача F4) остаются контрактами **поведения** — «посчитай фазу»,
«прими команду», — а не воротами к данным.

## 2. Таблицы и идентификаторы

**Каждый вид сущностей — одна таблица `StateTable`** (`state_table.h`): плотный
`std::vector` строк плюс параллельный вектор идентификаторов и обратный индекс id → строка.

| Правило | Зачем |
|---|---|
| **Строки плотные, без дыр** | Параллельный проход режет диапазон строк на куски |
| **Удаление — перестановкой с последней** | Плотность сохраняется; порядок строк не несёт смысла |
| **Id монотонные, никогда не переиспользуются** | Протухшая ссылка читается как «нет», а не как чужак |
| **Ссылки между сущностями — только id** | Строки переезжают, буферы копируются, id вечен |
| **Строки — структуры (AoS), не SoA** | Читаемость; масштаб — тысячи строк, профилировать рано |

**Идентификаторы двух родов** (`ids.h`): `EntityId` (32 бита, выдаётся на ходу — житель,
семья, юнит, поле, стадо) и `DefId` (16 бит, номер строки балансовой таблицы — культура,
ресурс, тип юнита). `DefId` — это плотный индекс: количества по видам ресурсов лежат в
обычном векторе (`ResourceAmounts`). В сохранении рядом с `DefId` пишутся строковые ключи
таблиц: загрузчик перепривязывает индексы, если таблицу редактировали.

## 3. Двойной буфер

**`WorldState` — значение.** Копирование — это снимок мира целиком; хранение состояния
дважды принято архитектурой ([Архитектура §7е](../../manual/technical/50-architecture.md#7е-многопоточность-и-взаимодействие-подсистем)).

| Следствие | |
|---|---|
| В состоянии нет указателей и хэндлов наружу | Только данные и `std::vector` |
| Сохранение — сериализация одной структуры | Загрузка — обратно, плюс перестройка индексов |
| Проверка детерминизма — сравнение двух прогонов | Один поток против многих |

Дисциплину чтения-записи и сам обмен буферов формализует [контракт цикла шага](53-step-cycle.md).
Модель состояния гарантирует лишь то, что буфер **можно** дёшево копировать и сравнивать.

## 4. Параллельный проход: единица работы по фазам

Фазы шага заданы архитектурой. Для каждой параллельной фазы фиксируется **единица
параллелизма** — то, чьи строки делятся между потоками:

| Фаза | Единица | Почему именно она |
|---|---|---|
| 2. Потребности жителей | **Семья** | Еда списывается из семейной кладовой: проход по жителям писал бы в семью из разных потоков |
| 4. Производство | **Юнит** (поле — тоже строка своей таблицы) | Юнит пишет только свои буферы и своё поле |
| 5. Логистика | **Юнит** | В первой фазе проекта — заглушка «мгновенная доставка» |
| 6. Метрики и агрегаты | **Семья** | Довольство считается на семью |

**Структурные изменения таблиц — добавление и удаление строк — только в однопоточных
фазах** (решения, события). Рождение, смерть, свадьба, постройка — это фаза 3 или 7,
никогда не параллельный проход.

## 5. Числа и единицы измерения

**Всё, что обязано сходиться копейка в копейку, — целые числа. Плавающая точка — только
для игровых метрик** (`quantities.h`).

| Величина | Тип | Единица |
|---|---|---|
| **Масса любого ресурса** | `Grams` = int64 | **Граммы.** Жидкости — по массе; баланс склада сходится точно |
| **Трудодни** | `TrudodniHundredths` = int32 | Сотые: ставки 0.5–2.0 представимы точно |
| **Деньги** | `Kopecks` = int64 | Копейки |
| **Метрики 0–100** | `Metric` = float | Сытость, здоровье, износ, плодородие, довольство |
| Доли и множители | `Ratio` = float | Прогресс цикла, веса формул |
| Координаты | `Meters` = float | Карта 10 × 10 км, начало в юго-западном углу |

**Правила плавающей точки** (ради «один поток = много потоков» и сверки Clang против MSVC):
только float32 в состоянии; без fast-math; contraction выключен флагами сборки; редукции
по сущностям — строго в порядке строк, а не в порядке завершения потоков.

## 6. Время: один счётчик, три шкалы

| Шкала | Тип | Что мерит |
|---|---|---|
| **Тик** | `Tick` | Фиксированный шаг симуляции — единственные монотонные часы. **Один тик — один игровой час, 24 в сутках** ([цикл шага §1](53-step-cycle.md#1-один-шаг--один-игровой-час)) |
| **Сутки** | `SimDay` | Целые сутки от старта кампании. Вся календарная арифметика — чистая функция от них |
| **Биологический возраст** | производный | Ускорение ×4 — параметр в таблицах; в состоянии хранится только день рождения |

Календарь: **4 суток в месяце, 48 в году, неделя из 7 суток идёт сквозь месяцы** —
структура зафиксирована константами (`calendar.h`), это дизайн, а не баланс.
`CalendarState` держит тик, сутки и кэш разбивки (дата, день недели, сезон), который
обновляет фаза времени.

## 7. Случайность

| Правило | |
|---|---|
| **Один последовательный ГПСЧ мира** (`RngState`, 128 бит) | Двигается только в однопоточных фазах |
| **В параллельных фазах — счётчиковый розыгрыш** | Число выводится из (seed, tick, id сущности) |
| `world_seed` фиксируется при создании мира | Один seed и те же команды — тот же мир |

Так порядок работы потоков не влияет на выпавшие числа ни при каком раскладе. Конкретный
алгоритм — выбор реализации `core_common` (задача O1); для остальных состояние ГПСЧ непрозрачно.

## 8. Карта таблиц: что появится и кто пишет

`WorldState` (`world_state.h`) растёт **добавлением** полей по этапам плана; перестройка
существующих — событие. Сейчас в нём: календарь, погода, эпоха, seed, ГПСЧ, репутации
председателя (STUB), план как числа (STUB).

| Блок | Этап | Пишет (фаза) | Главные читатели |
|---|---|---|---|
| `calendar`, `weather` | 1–2 | Время и погода (1) | Все |
| `residents` | 3 | Потребности (2, по семьям), Решения (3) | Производство, метрики, демография |
| `families` | 3 | Потребности (2), Метрики (6), Решения (3) | Потребности, события, демография |
| `fields` | 4 | Производство (4) | Решения, логистика |
| `units` (буферы — в строке юнита) | 4–5 | Производство (4), Логистика (5) | Решения, метрики |
| `herds` | 4 | Производство (4) | Решения |
| `chairman`, `plan` | заглушки | События (7) | Отчёты |
| `ledger` — потоки года | 7 | Последовательные под-шаги в месте потока; свёртка параллельного — События (7) | **Никто в симуляции.** Ведомость прогона ([`68-run-ledger.md`](68-run-ledger.md)) |
| `orders` — книга распоряжений | фаза II, А1 | **Дописывает только движок шага**, до фазы 1; статусы двигает потребитель в Решениях (3); терминальные снимают События (7) | Под-шаги слота 3 — каждый свои виды ([`70-boundary.md` §2](70-boundary.md#2-команды--это-книга-распоряжений)) |
| `step_events` — ящик шага | фаза II, А1 | Чистит движок после копии; дописывают последовательные под-шаги и События (7) | **Никто в симуляции.** Граница забирает между шагами; **не сохраняется** ([`70-boundary.md` §4](70-boundary.md#4-события-поток-который-накапливается-и-забирается)) |

Назначения на работу — поля строки **жителя** (текущее и отложенное), а не отдельная
таблица: у назначения нет собственной жизни.

## 9. Что состоянием не является

**Всё выводимое — выводится, а не хранится** ([Архитектура §4](../../manual/technical/50-architecture.md#4-граница-между-модулями)).

| Не хранится | Считается из |
|---|---|
| Производительность и грузоподъёмность жителя | Метрики, склонности, возраст |
| Рейтинг семьи, культурный уровень села | Существующие метрики |
| «Живые сигналы» — бельё, дым, очереди | Состояние ядра, каждый кадр, на стороне графики |
| Агрегаты по селу и бригадам | Таблицы семей при показе |

Исключение делается только для величины, которую читают несколько фаз за шаг, — тогда её
кэширует фаза-владелец (пример — разбивка даты в `CalendarState`).
