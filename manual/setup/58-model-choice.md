# Какая модель на какую задачу

> **Какие задачи чьи — в плане:** [`51-phase1-plan.md`](../plan/51-phase1-plan.md) §9а и
> колонка «Модель» у каждого этапа. Это источник, здесь он не переписывается.
> Состав агентов проекта — `../../manual/process/54-agents.md`.

**Здесь — три вещи, которых в плане нет:** чем «старшая» и «обычная» являются на деле, как
задача делится между ними, и что одна сессия оставляет другой, чтобы та не выводила всё
заново.

---

## 1. Привязка имён

| В плане | Модель | На что |
|---|---|---|
| **Старшая** | **Fable** | **Проектирование интерфейсов, важный код, диагностика** |
| **Обычная** | **Opus** | Реализация за готовым контрактом, тесты, инфраструктура, рутина |

**Fable дорогая — это и есть причина делить.** Каждая задача, ушедшая к ней без нужды,
оплачена зря; каждая задача проектирования, ушедшая к Opus, оплачивается потом переделкой.

---

## 2. Что идёт к Fable

**Признак один: ошибку дорого откатывать.**

| Задача | Почему |
|---|---|
| **Интерфейсы подсистем** | Контракт на всю разработку. Правка интерфейса — событие (`CLAUDE.md` §8) |
| **Раскладка данных и модель состояния** | Переделка отзовётся в каждом модуле |
| **Границы модулей, граф зависимостей** | «Слои и иерархии переделывать дорого» (`CLAUDE.md` §11) |
| **Цикл шага, фазы, двойная буферизация** | Ошибка здесь ломает детерминизм — жёсткое требование |
| **Форматы, живущие дольше кода** | Таблицы, сохранения: их менять больно даже когда легко |
| **Разбор расхождений и недетерминизма** | Диагностика, а не написание кода |
| **Подбор параметров баланса** | Многофакторная задача без единственного ответа |

## 3. Что идёт к Opus

| Задача | Почему |
|---|---|
| **Реализация за готовым интерфейсом** | Контракт уже задан, свобода внутри полная |
| **Unit-тесты и прогоны** | Обязательны, но механические |
| **Инфраструктура, сборка, скрипты** | Проверяются запуском, ошибка видна сразу |
| **Документация** | |
| **Правки по находкам статанализа** | Кроме структурных — те останавливают цикл |
| **Заглушки `STUB`** | Сигнатура финальная, тело нейтральное |

**Цикл `/check_static_new` и его агенты идут на Opus.** Находка, требующая структурной
правки, цикл **останавливает** ([`56-static-analysis-and-tests.md`](56-static-analysis-and-tests.md))
— вот она и есть точка передачи к Fable.

## 4. Задача смешанной сложности — делится

**Если в задаче есть и проектирование, и реализация, это две задачи, а не одна.**
Иначе дорогая модель оплачивает написание циклов, а дешёвая — проектирует контракт.

**Шов проходит по виртуальному интерфейсу.** Это не совпадение: проект и так требует
абстрактный интерфейс на границе подсистемы (`CLAUDE.md` §8). Тот же шов делит работу
между моделями.

```
   FABLE                  контракт                    OPUS
   проектирует     ──→  include/<модуль>/i_*.h   ──→  генерирует код
   чистые виртуальные    ни одного тела               subprojects/<модуль>/*.cpp
   методы, Doxygen,                                   реализации, заглушки STUB,
   @threading, владение                               unit-тест
```

### Интерфейс и генерация кода — всегда разные задачи

**Цена ошибки в интерфейсе высока: это контракт на всю разработку, и его правка —
событие** (`CLAUDE.md` §8). Поэтому проектирование виртуального интерфейса не смешивается
с написанием кода **никогда** — даже с телами заглушек.

| Задача Fable: спроектировать интерфейс | Задача Opus: написать код |
|---|---|
| Чисто виртуальные методы, `= 0` | **Любые тела, включая `STUB`** |
| Doxygen: контракт, предусловия, единицы, диапазоны | Реализующие классы |
| `@threading` и фаза шага, из которой зовут | Фабрики, регистрация, склейка |
| Владение и время жизни | Unit-тест на интерфейс |
| Что нельзя менять, не объявив событием | |

**Две независимые причины, и обе весомые:**

1. **Качество.** В смешанной задаче внимание уходит на код, который надо заставить
   работать, а контракт получается «достаточным для этой реализации» вместо правильного.
   Интерфейс, подогнанный под первую реализацию, — это и есть та ошибка, которую потом
   дорого откатывать.
2. **Стоимость.** Генерация кода — самая объёмная часть работы. По дорогой ставке она
   оплачивается зря.

**Готовность задачи Fable проверяется механически:**

```bash
bash claude/tools/core_build.sh syntax include/<модуль>/*.h
```

Заголовок компилируется, тел в нём нет, `@threading` на месте. Реализации ещё нет — и её
отсутствие не должно мешать заголовку собираться.

> **Границы не переходить:** **один интерфейс на подсистему, а не на каждый класс**
> (`CLAUDE.md` §8). «Проектирование интерфейсов» — не повод плодить абстракции: цепочка из
> трёх-четырёх интерфейсов заставляет искать настоящий код и вредна ровно так же, как её
> отсутствие.

| Признак того, что делить надо | |
|---|---|
| В формулировке есть «спроектировать **и** написать» | Две задачи |
| Строка плана помечена **Старшая**, а соседние — обычной | Уже поделено, не сливать обратно |
| Задача трогает границу между модулями и внутренности сразу | Две задачи |
| Непонятно, какой модели отдавать | **Признак того, что задача слишком крупная** |

## 5. Что передаётся между сессиями

**Сессии разных моделей друг друга не видят.** Всё, что не оставлено в файлах, придётся
выводить заново — и это ровно те токены, которые экономятся.

| Что | Куда | Отслеживается git |
|---|---|---|
| **Контракт** | Заголовок в `include/<модуль>/` — Doxygen, `@threading`, тела `STUB` | **Да** |
| **Разметка модулей** | `subprojects/<модуль>/CMakeLists.txt`, зависимости объявлены явно | **Да** |
| **Решение, связывающее руки дальше** | Сказать человеку; место решения — реестр решений корневого мануала | Да, у root |
| Рабочие заметки, отвергнутые варианты | `claude/design/` | Нет |

**Сессия Fable заканчивается не разговором, а файлами.** Заголовок, который компилируется,
и `CMakeLists.txt`, который собирается, — вот её результат. Сессия Opus начинает с них и
проектных документов, а не с пересказа чужих рассуждений.

**Обратный ход тоже есть.** Задача на Opus, упёршаяся в решение, которого нет в документах,
**останавливается и спрашивает** (`CLAUDE.md` §6) — она не додумывает. Это и есть штатная
передача обратно к Fable.

## 6. Рекомендация перед началом работ

**Выдаётся человеку до старта, на двух уровнях.**

| Уровень | Что содержит |
|---|---|
| **Перед фазой** | Сводка: доля Fable по этапам, где сосредоточена, чем оправдана |
| **Перед этапом** | Поимённый разбор задач: модель, порядок, зависимости |

Формат разбора — таблица:

| Задача | Модель | Почему | После чего |
|---|---|---|---|
| Что делается | Fable / Opus | Одной строкой | От какой задачи зависит |

Плюс три вещи, без которых рекомендация бесполезна:

1. **Порядок.** Задачи Fable идут первыми — реализация опирается на контракт. Задача Opus,
   запущенная раньше своего интерфейса, будет переписана.
2. **Что задача Fable обязана оставить.** Названный файл, а не «описание архитектуры».
3. **Что можно вести параллельно.** Независимые ветки называются явно.

**Человек рекомендацию утверждает или правит.** Это предложение, а не план работ:
экономия токенов — его цель, ему и решать, где она уместна.
