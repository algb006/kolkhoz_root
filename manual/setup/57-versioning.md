# Версии: что нумеруется и когда поднимается

> Раскладка проекта — [`55-project-layout.md`](55-project-layout.md).
> Порядок сдачи — [`56-static-analysis-and-tests.md`](56-static-analysis-and-tests.md).

**Номер лежит в файле, а не в коде.** Две копии одного числа расходятся, и устаревшей
всегда оказывается та, которую никто не правит.

---

## 1. Два номера, и они независимы

| Файл | Что нумерует | Формат |
|---|---|---|
| [`VERSION`](../../VERSION) | **Библиотека ядра** | `major.minor.patch` |
| [`VERSION_SAVE`](../../VERSION_SAVE) | **Двоичный формат сохранения** | целое число |

**Разделены намеренно.** Формат сохранения переживает много выпусков библиотеки: можно
поднять `VERSION` десять раз, ни разу не тронув раскладку сохранённого состояния. И
наоборот — одна правка, ломающая старые сохранения, должна быть видна сама по себе, а не
растворяться в очередном `0.4.7`.

**Игры здесь нет.** Её пока не существует, и версия у неё будет своя — на стороне UE, по
своей шкале. **Версия ядра — не версия игры.** Когда игра появится, её номер заводится
отдельно и с этими файлами не связывается.

---

## 2. Когда поднимать `VERSION`

| Часть | Поднимается, когда |
|---|---|
| **major** | **Сломалась граница ядра и слоя графики.** Старый потребитель не соберётся или не заработает |
| **minor** | **Сдан этап** из [плана первой фазы](../plan/51-phase1-plan.md): время, жители, земля, труд |
| **patch** | Сдан отдельный модуль или исправление |

**Пока идёт первая фаза, major остаётся нулём.** Граница с UE ещё не написана, ломать
нечего. Первый выпуск с настоящим интерфейсом для движка — это `1.0.0`.

**Один бамп на сдаваемый коммит**, не на каждую правку внутри работы над модулем.

---

## 3. Когда поднимать `VERSION_SAVE`

**Только тогда, когда старый файл сохранения перестаёт читаться как есть.**

| Изменение | Бамп |
|---|---|
| Добавили поле в сохраняемую структуру | **Да** |
| Убрали или переставили поля | **Да** |
| Сменили тип поля, ширину, порядок байт | **Да** |
| Изменили состав сохраняемых сущностей | **Да** |
| Переименовали переменную, переписали функцию | Нет |
| Изменили значение по умолчанию в таблице данных | Нет |

**Бамп формата сохранений — событие, как смена интерфейса подсистемы**
(`CLAUDE.md` §8, §10). Он означает, что чьи-то сохранения перестали открываться, и об этом
надо сказать вслух, а не заметить в диффе.

> **Правило чтения:** сохранение с номером **выше**, чем у сборки, **отвергается**, а не
> угадывается. Сборка не знает, что добавили после неё.

Совместимость со старыми номерами — отдельное решение, которого в документах дизайна пока
нет. До него читать умеем только свой номер.

---

## 4. Как это видно из кода

CMake читает оба файла и генерирует заголовок:

```
   VERSION       ─┐
                  ├─→  build/generated/include/core_common/version.h
   VERSION_SAVE  ─┘         шаблон: include/core_common/version.h.in
```

```cpp
#include "core_common/version.h"

core::kCoreVersionMajor    // 0
core::kCoreVersionMinor    // 1
core::kCoreVersionPatch    // 0
core::kCoreVersionString   // "0.1.0"
core::kSaveFormatVersion   // 1
```

| Правило | |
|---|---|
| **Правится файл, а не заголовок** | Сгенерированная копия живёт в `build/` и в git не попадает |
| **Правка файла = перенастройка** | `CMAKE_CONFIGURE_DEPENDS` не даст собрать со старым номером |
| **Формат проверяется** | `VERSION` не `major.minor.patch` или `VERSION_SAVE` не число — ошибка настройки, а не молчаливый мусор |

**Ни хеша коммита, ни времени сборки в заголовке нет.** Они переписывали бы его при каждом
коммите, обнуляли ccache и делали сборку невоспроизводимой — ради сведений, которые и так
берутся из `git log`.

```
  make version    показать оба номера
  make info       они же в общей сводке настроек
```

## 5. Чего пока не нумеруем

**Осознанные пропуски, а не забытые.**

| Что | Почему нет |
|---|---|
| **Версия игры** | Игры нет. Версия будет своя, на стороне UE |
| **Версия интерфейса ядро↔UE** | Интерфейса нет: вторая фаза. Когда появится — это кандидат на третий файл |
| **Версия формата таблиц данных** | Формат таблиц не выбран (CSV или JSON) — решение открыто, [план §3](../plan/51-phase1-plan.md) |
| Версия отчётов статанализа | Данные служебные, живут вне git |

---

## 6. Сдача

| Шаг | |
|---|---|
| **Сдаёшь модуль** | Поднять **patch** |
| **Сдаёшь этап плана** | Поднять **minor**, patch обнулить |
| **Тронул раскладку сохранения** | Поднять `VERSION_SAVE` **и сказать об этом** |

Бамп идёт **в том же коммите**, что и сдаваемая работа. Отдельный коммит «bump version»
не заводить: он отвязывает номер от того, что этот номер обозначает.
