# Статанализ и тесты: что обязательно при сдаче

> Раскладка проекта и сборка — [Раскладка проекта](55-project-layout.md).
> Правила написания кода — [`../../CLAUDE.md`](../../CLAUDE.md) §10, §14.

**Этот документ — источник правды для правила.** Сам механизм живёт в файлах, которые в git
не попадают (`claude/`, `.claude/` — они под `.gitignore` и хранятся в архиве
`/claude_backup`). Правило должно пережить потерю механизма, поэтому записано здесь.

---

## 1. Два обязательства

| Что | Когда обязательно |
|---|---|
| **Unit-тест на модуль** | Модуль (связка `.h` + `.cpp`) не сдан, пока теста нет и он не прогнан |
| **Статанализ `/check_static_new`** | При сдаче модуля и **при сдаче фазы разработки кода игры** |

**Прочие тесты — по необходимости.** Прогоны симуляции, сверка с расчётами, проверки на стыке
подсистем заводятся тогда, когда есть что проверять, и живут в `tests/run/`.

---

## 2. Unit-тест на каждый модуль

```
   subprojects/core_time/     модуль
        │
        └── tests/unit/core_time/     ← обязательный тест, имя папки = имя модуля
                 приложение unit_core_time, метка CTest "unit"
```

| Правило | |
|---|---|
| **Имя папки теста = имя модуля** | Связь механическая, а не по договорённости |
| **Объявление** | `kolkhoz_add_unit_test(core_time main.cpp)` |
| **Метка CTest** | `unit` — `make unit` гоняет ровно обязательный набор |
| **Проверка полноты** | `make check-tests` |

`make check-tests` ловит обе стороны расхождения: модуль без теста и тест без модуля
(переименовали модуль — тест остался прикрывать пустоту).

```
  make unit          только обязательные тесты модулей
  make test          весь набор, включая прогоны из tests/run/
  make check-tests   на каждый ли модуль есть тест — и три проверки сверх того
```

**`check-tests` — не только про тесты.** В нём собрано то, что проверяется без сборки и обязано
проверяться всегда:

| Проверка | Чем | Что ловит |
|---|---|---|
| Модуль без теста и тест без модуля | `scripts/check_module_tests.sh` | Переименованный модуль с тестом, прикрывающим пустоту |
| Дисциплина включений | `scripts/check_includes.py` | Ребро, которого нет в `CMakeLists.txt` |
| Терминаторы граничных перечислений | `scripts/boundary_enums.py` | Перечисление на границе без `kXxxCount` |
| **Таблицы против базы дизайна** | **`scripts/check_tables_export.py`** | **Выгрузку, которая до дерева не доехала.** Без корневого дерева пропускается: ядро обязано собираться отдельно |
| **Перекличка видов событий** | **`scripts/event_sites.py`** | **Вид события, который никто не пишет.** Список берётся из перечисления, а не из кода; намеренное молчание объявляется `@no_emit` с причиной ([Граница §4а](../70-boundary.md)) |

**Библиотека модульных тестов не выбрана** — в документах дизайна решения нет. Пока
обходимся обычными исполняемыми файлами с кодом возврата: `0` — прошёл, иначе — упал. Этого
хватает, выбор откладывается до реальной нужды.

## 3. Статанализ: `/check_static_new`

Команда гоняет цикл **сборка → тесты → анализ → правки** по дельте от последней успешной
проверки, на четыре класса дефектов: **UB**, **Memory**, **RACE**, **DEADLOCK**.

| | |
|---|---|
| **Где живёт команда** | `.claude/commands/check_static_new.md` — **в git не попадает** |
| **Хелпер сборки** | `claude/tools/core_build.sh` — тоже не попадает |
| **Данные и отчёты** | `claude/analysis/` — тоже не попадают |
| **Откуда взято** | Посылка из родительского проекта, адаптирована под ядро |

**Цикл правит исходники и работает прямо на `main`** — у ядра один разработчик и одна
ветка, она же рабочая, защищать отдельной веткой нечего. Вместо неё дерево защищает
снимок, который цикл делает **до первой правки**: он единственный способ отделить правки
цикла от незакоммиченной работы человека. Отсюда же запрет на `git stash` и
`git checkout -- .` внутри цикла — именно они эту работу и снесли бы.

Отказ один: **detached HEAD**. Коммит сдачи ушёл бы туда, где на него ничто не ссылается.

Режим `--once` — один проход только для чтения, без сборки и правок.

### Что цикл проверяет и чего не делает

| Делает | Не делает |
|---|---|
| Анализ **по дельте**, а не всего дерева | Полный аудит кодовой базы |
| Чинит `crit` и внесённые самим циклом `high` | Не пишет код ради `med` и `low` |
| Копит остальное в `claude/analysis/OPEN_ITEMS.md` | Не переоткрывает разобранное заново |
| Правит комментарии **одним проходом в конце** | Не ревьюит прозу в каждой итерации |

**Потолок — восемь итераций, и он жёсткий.** Формулировка «гоняй, пока не станет чисто» его
не снимает: цикл ревьюит собственные свежие правки, поэтому пустой проход недостижим по
построению. Условие успеха — **правки цикла не внесли `crit` и `high`**, а не «находок нет».

## 4. Однопоточный модуль не проверяется на гонки

**Метка `@threading` в шапке заголовка решает, какие классы анализа запускать.** Она
существует ровно за этим: анализатор не ищет гонки там, где их не может быть
(`CLAUDE.md` §10).

| Метка модуля | Классы анализа |
|---|---|
| **`SINGLE_THREADED`** | **UB и MEM. RACE и DEADLOCK не запускаются** |
| `PARALLEL_READONLY` | все четыре |
| `PARALLEL_WRITE` | все четыре |
| **метки нет** | **все четыре**, плюс находка «метка отсутствует» |

**Два предохранителя, оба в сторону «лучше проверить лишнее»:**

1. **Метки нет — гоняем всё.** Метка обязательна; её отсутствие — само по себе находка.
   Иначе «забыл метку» стало бы способом обойти проверку.
2. **Метка говорит `SINGLE_THREADED`, а в коде есть `std::thread`, мьютекс, атомик или
   задача enkiTS** — это находка класса RACE серьёзности **критическая**, и модуль
   проверяется на гонки **всё равно**. Смена метки — событие, молча ей верить нельзя.

Есть и третий случай: **две разные метки внутри одного модуля**. Это дефект, а не выбор —
тоже все четыре класса и находка.

Классификация делается **скриптом, а не глазами**: `claude/tools/threading_scope.sh` строит
по списку файлов таблицу «файл → модуль → метка» и отдельный список тех файлов, которые
получают RACE и DEADLOCK. Метка модуля берётся только из его собственных каталогов —
`include/<модуль>/` и `subprojects/<модуль>/`, поэтому **папка в `include/` называется точно
как модуль** ([Раскладка проекта](55-project-layout.md)).

Находки про метку — единственные находки про документацию, которые цикл чинит **сразу**, а не
в общем doc-проходе: от метки зависит состав классов следующей итерации.

## 5. `tests/` вне механизма

**Статанализ каталог `tests/` не обслуживает.** Там анализ упрощённый и только по
необходимости — флагом `--with-tests`.

| Почему | |
|---|---|
| **Дефект в тесте виден как упавший тест** | Он не уезжает в поставку |
| **Тест — леса, а не конструкция** | Полный аудит лесов ради трёхстрочной правки бессмыслен |
| **Цикл ревьюит собственные правки** | Расширение области — прямой путь к несхождению |

Упрощённый проход отличается по всем осям: только **UB и MEM**, только по хункам, без
разбора комментариев, и находки **сдачу не блокируют** — уходят в `OPEN_ITEMS.md` с пометкой
`tests`.

**Когда включать `--with-tests`:** тест сам стал сложным (генератор данных, сверка с
эталонными числами), тест падает непонятно, прогон даёт разные числа от запуска к запуску.
В остальных случаях — не включать.

## 6. Порядок сдачи

### Сдача модуля

```
  1. make check-tests                    на модуль есть unit-тест
  2. make unit                           тест проходит
  3. /check_static_new                   цикл до успешного прохода
  4. коммит                              область схлопывается, следующий цикл дешевле
```

### Сдача фазы разработки кода игры

Всё то же, плюс требования `CLAUDE.md` §14:

| Проверка | Чем |
|---|---|
| **Собирается в виртуалке без предупреждений** | `make rebuild` — `-Werror` включён |
| **Собирается на хосте под MSVC** | `/check_static_new --flavour` или `make win` |
| **Весь набор тестов проходит** | `make test` |
| **Один поток = много потоков** | Тест `determinism` в наборе: 1 против 4 рабочих потоков, побайтово |
| **Баланс одной культуры сходится** | `oat_balance`: пятнадцать лет, все строки, двигающие грамм овса, и невязка обязана быть нулём. **Грамм, ушедший дорогой, которую никто не назвал, виден только так** ([Сверка §13.15](../balance/69-reconciliation.md)) |
| **Климат не поехал** | `weather_shape`: 200 лет одной фазы времени против безпамятного двойника той же таблицы — среднее сезона, доля мокрых суток, средний суточный размах ([Сверка §13.11](../balance/69-reconciliation.md)) |
| **Прогон сходится с каноном** | `thirty_years`: жителей 30-го года **не ниже пола канона**. Пол утверждается, потолок печатается наблюдением — его кромка внутри шума прибора ([Сверка §13.8](../balance/69-reconciliation.md)) |
| **Промотка держит норматив** | `thirty_years`: самые дорогие игровые сутки прогона ≤ 2 с |
| **Статанализ прошёл по всей дельте фазы** | `/check_static_new` |
| Форматирование, размеры файлов, `@brief`, `@threading`, `STUB` | `make format-check`, ревью |

### Долговой список обязан иметь голову

**`claude/analysis/OPEN_ITEMS.md` начинается секцией «что открыто сейчас», и она обновляется
проходом, а не памятью.** До 4 сентября 2026 её не было: закрытие записывалось зачёркиванием
исходной строки на сотни строк выше, и вопрос «что открыто» не отвечался иначе как полным
перечитыванием. **Две строки при этом врали в сторону «открыто»** — обе были починены этапом 4 и
фазой 2, а зачёркнуты не были.

> **Журнал, который нельзя прочитать без памяти о нём, — это не список долгов, а их архив.**

---

**Маркер базы сдвигается только при успешной сдаче.** Прерванный или досрочно остановленный
прогон маркер не трогает: иначе дельта, которую никто не анализировал, будет похоронена.

## 6в. Замер, взятый поверх движущегося предмета, выглядит успешным

**Заведено 12 сентября 2026, после третьего случая за день. Прибор был исправен все три раза —
двигался ПРЕДМЕТ.**

| Бекап | **«Не гнать поверх идущей сборки»** — архив возьмёт половину записанного |
| Сверка | **«Фотографию не ретушируют, её переснимают — но когда предмет перестал двигаться».** Два пересъёма за день дают два снимка двух разных хозяйств и ни одного ответа |
| **Порча поверх идущего набора** | Мой случай, и он здесь потому, что он про ЭТОТ харнесс |

### Что было

**Приёмочный набор шёл в фоне, и я в это же время запустил порчу — оба на одном каталоге
сборки.** Набор собрал одни цели до порчи, другие после и **дал красный на `labor_year`,
которого в дереве не было.** Проверил отдельно — зелёный.

**Вердикт я выбросил и переделал по одному, но заметил это только потому, что красный был
неправдоподобен.** Окажись он правдоподобным — я бы чинил то, что не сломано, по показанию
прибора, мерившего два разных дерева сразу.

### Правило

| **Один каталог сборки — один прогон** | Порча, приёмка, `--flavour`, ручной запуск двоичного файла: **в каждый момент что-то одно** |
| **Порча начинается после того, как набор кончился** | Не «пока он идёт, я быстренько» — это ровно та же составная команда, что берёт бекап поверх кука |
| **Красный, пришедший из параллельного прогона, НЕ ЗАСЧИТЫВАЕТСЯ ни в какую сторону** | Ни как находка, ни как «показалось». Прогон переснимается целиком |

> **Вниманием это не ловится, и в этом вся суть.** Замер выглядит успешным: число пришло, вердикт
> напечатан, форма правильная. **Ловится замком или проверкой перед прогоном** — как у
> Windows-хоста, где ровно от этого заведён `tools/host.sh take`.

### Портится не только замер — портится ДЕРЕВО, и это дописано через час

**Первая редакция этого параграфа говорила про замер и молчала про файлы, и меня же на этом и
поймали — тем же часом, тем же классом.**

**Что было.** Фоновая команда с порчей упала на середине (`exit 1`) и **не дошла до строки
восстановления**. Я тем временем снял свою копию для следующей порчи — **поверх уже испорченного
файла**, — и восстановил потом из неё. В дереве остался литерал `false &&`, выключавший всю
сданную механику. **Нашёл цикл статанализа, не я**, и до него успел отдать координатору числа,
не зная, что мерил.

| **Порча восстанавливается ПРОВЕРКОЙ, а не командой восстановления** | `cp` из копии — это намерение. Проверка — это факт |
| **Проверка простая и обязательная** | `grep -rn 'false &&' subprojects/ include/` перед сборкой сдачи. Три секунды |
| **Копия для порчи снимается с ЧИСТОГО дерева** | Снятая поверх испорченного, она увековечивает порчу вместо того, чтобы её откатить |
| **Составная команда `порча && сборка && прогон && восстановление` — НЕ откат** | Упавшее звено в середине оставляет дерево испорченным, и код возврата об этом скажет только тому, кто его прочтёт |

> **«Думал, что откатил» и «откатил» выглядят одинаково ровно до следующей сборки.** Разницу
> между ними видит только тот, кто ищет след порчи, а не тот, кто помнит, что отдавал команду.

**Родня:** [§6.2а цикла](../../.claude/commands/check_static_new.md) — порча проверяется счётом,
а не фактом покраснения. **Здесь счёт бы не спас:** порча дала бы верное число покраснений плюс
одно чужое, и разобрать их было бы нечем.

## 6б. Демпфер: что цикл чинит, а что записывает

**У этого правила не было дома до 12 сентября 2026 — оно жило в посылках и в самой команде
`/check_static_new`, то есть в файле, который в git не попадает.** `boss` пошёл за ним и не
нашёл ни здесь, ни в `core/CLAUDE.md`. **Правило без дома не дописывается: чтобы добавить
вторую половину, нужно место, куда её положить.** Отсюда и вся его история, включая оговорку
ниже, которой не было четыре дня подряд.

### Само правило

| | `origin=introduced` | `origin=pre-existing` |
|---|---|---|
| `crit` | чинить в этой итерации | чинить, минимально |
| `high` | чинить в этой итерации | **вердикт + `OPEN_ITEMS.md`**, не чинить |
| `med` | **вердикт, кода не писать** | вердикт |
| `low` | **вердикт, кода не писать** | вердикт |

**Зачем.** Правки цикла — главный источник его же находок: в замере родительского проекта
**98 % находок каждого прохода были новыми**, и садились они на строки предыдущего прохода
вдвое плотнее, чем на случайное место файла. **Демпфер защищает не от работы, а от расползания
ОБЛАСТИ правки** — без него цикл сдачи не кончается никогда.

**`pre-existing high` не чинится внутри цикла** отдельно: файл попал в область из-за
трёхстрочной правки, а не потому, что его решили аудировать.

### Оговорка: находка ВНУТРИ сдаваемого предмета — это и есть область

**Заведена 12 сентября 2026 вердиктом `boss`, после сдачи `kUnsealFund`.**

> **Находка внутри сдаваемого предмета область не расширяет — она и ЕСТЬ эта область.**

**Мерка одна и проверяемая, и она не про серьёзность:**

| **Уедет ли дефект вместе с тем, что я сдаю?** | **Да** — чинить сейчас, каким бы ни был уровень |
| | **Нет** — вердикт и долговой проход, и тут правило не двигается ни на шаг |

**Что демпфер держит по-прежнему:** соседний модуль, старая функция, попутно замеченное. Это
снаружи сдаваемого, и это долговой проход.

**Случай, на котором оговорка родилась.** Цикл сдачи `0.17.84` дал пять находок уровня `med`
внутри нового глагола `kUnsealFund`, найденных до того, как он хоть раз уехал: `resize` по
непроверенному id ресурса (одна опечатка — и партия больше не сохраняется), знаковое
переполнение внутри самой проверки на потолок, `FundKind::kNone`, доходящий до потребителя мимо
границы, и скриптовая правка, стиравшая зимнюю распечатку в первый день весны.

> **Отложить их значило сдать глагол с известной дырой и запиской в реестре.** Это «неснятое
> подозрение живёт в тексте как находка», вывернутое наизнанку: **подозрение снято, а дыра
> осталась.**

### И то, что демпфер НЕ отменяет

**Починка по оговорке проверяется той же порчей и тем же счётом**, что и всякая другая
([§6.2а цикла](../../.claude/commands/check_static_new.md) — порчей проверяют счётом, а не
фактом покраснения). В том же цикле одна порча дала **ноль покраснений вместо одного**, потому
что испорчена была соседняя строка. **Порча, попавшая не туда, засчитана быть не может**, и
отличает её от слабой проверки только счёт.

## 6а. Формы дефектов, найденные трижды

**Третье повторение — то место, где дешевле описать КЛАСС, чем чинить экземпляры**
(решение `boss`, 8 сентября 2026). Здесь не список находок — реестр их у
`claude/tools/debt.py`, — а описание формы, чтобы четвёртый случай нашёлся раньше, чем
будет написан.

### Система держит указатель на собственный член и остаётся копируемой

**Найдено дважды:** `core_production/production_system.cpp` (`phase_(config_)`) и
`core_residents/residents_system.cpp` (`needs_phase_(food_, …)`, `metrics_phase_(config_, food_)`).

> **«Третий раз та же форма» я сказал 8 сентября 2026 и был неправ.** Третьей я счёл запись
> `MEM-003` по `core_labor/labor_system.cpp` — а там **другая** форма: индексация строкой
> жителя, которую сегодня прикрывает отказ проверок выше. `LaborSystem` держит конфигурацию по
> значению и читает её напрямую, объектов фаз с указателями внутрь у него нет.
> **Ключ реестра — `(класс, файл)`, и он честно сложил в одну запись два РАЗНЫХ предмета
> одного класса в одном файле;** счёт по нему даёт число записей, а не число форм. Класс
> описан здесь потому, что форма повторилась, — но повторилась она дважды, и запись, которая
> завышала бы счёт, стоила бы ровно того же, что и любое другое число, взятое из прозы.

Форма всегда одна: класс подсистемы хранит конфигурацию **по значению** и рядом — объекты фаз,
которым при постройке передан указатель или ссылка на эту самую конфигурацию. Копия класса
копирует и указатель, и он показывает в **чужой** член — в тот, что остался у оригинала.

| Почему сегодня недостижимо | Почему это всё равно форма, а не мелочь |
|---|---|
| Классы `final` и живут только за `unique_ptr` фабрики | Недостижимость держится на **соглашении вызывающего**, а не на типе |
| Копию никто не пишет | Её напишет тот, кто захочет «снимок системы» — и получит указатели в оригинал |

**Лечение — одна строка на класс:** `SomeSystem(const SomeSystem&) = delete;` вместе с
присваиванием. **Пишется в тот момент, когда у класса появляется член-указатель на соседний
член**, а не когда копию кто-то напишет: к тому дню это будет уже не профилактика, а разбор.

> **Признак, по которому форму видно без анализатора:** в конструкторе фазы стоит `&config_`
> или `*this`-производное. Всё, что берёт адрес собственного члена, обязано объявить, что
> объект неперемещаем и некопируем, — иначе адрес переживёт своего владельца.

## 7. Если механизм потерян

Файлы механизма не отслеживаются git — при потере восстанавливаются из архива
`/claude_backup`. Что должно быть на месте:

| Файл | Роль |
|---|---|
| `.claude/commands/check_static_new.md` | Сама команда: вся механика цикла |
| `claude/tools/core_build.sh` | Хелпер сборки: `preflight`, `build`, `test`, `syntax` |
| `claude/tools/threading_scope.sh` | Классификация файлов по метке `@threading` |
| `claude/analysis/` | Маркер базы, открытые пункты, отчёты, журналы |

**Что при этом остаётся в git и потерю переживает:** это правило, раскладка `tests/unit/`,
помощник `kolkhoz_add_unit_test`, `scripts/check_module_tests.sh` и цели `make unit` и
`make check-tests`. То есть обязательства сохраняются, восстанавливать нужно только
инструмент.
