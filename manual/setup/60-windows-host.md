# Windows-хост: настройка и сборка под MSVC

> Раскладка проекта и сборка в виртуалке — [Раскладка проекта](55-project-layout.md).
> Скрипты: [`scripts/win-setup.ps1`](../../scripts/win-setup.ps1) — настройка хоста,
> [`scripts/build-core.bat`](../../scripts/build-core.bat) — сборка на хосте,
> [`scripts/win-build.sh`](../../scripts/win-build.sh) — перенос и запуск с виртуалки.

---

## 1. Зачем нужен второй компьютер

```
   ВИРТУАЛКА (AlmaLinux 10)              ХОСТ (Windows 11 Pro)
   Clang, CMake, Ninja, ccache           MSVC из Build Tools
   основная разработка ядра        ──▶   сборка для линковки в UE
   прогоны симуляции                     игра и редактор UE
```

**Хост нужен только тогда, когда меняется библиотека, отдаваемая в UE.** Ядро обязано
собираться обоими компиляторами: расхождение между Clang и MSVC ловится сразу, а не в
редакторе через неделю ([Архитектура §7г](../../../manual/technical/50-architecture.md#7г-pipeline-разработки)).

**Основной цикл при этом остаётся в виртуалке** — там быстрее и там весь инструментарий.

---

## 2. Что ставится на хост и зачем

| Что | Зачем именно оно |
|---|---|
| **OpenSSH Server** | Штатный компонент Windows 11. Единственный вход на хост с виртуалки |
| **MSYS2** | Даёт `rsync` и POSIX-оболочку. **Без неё перенос не работает** — см. §5 |
| **Visual Studio Build Tools**, набор C++ | MSVC, Windows SDK, CMake и Ninja. Студия целиком не нужна |

**Рабочий каталог — `C:\MyGames\Kolkhoz\core-msvc`.** Это подпапка общей папки игры;
исходники ядра туда переносятся целиком, сборка кладётся в `build-msvc` внутри неё.

## 3. Как применить

Скрипт настройки лежит в репозитории ядра, а перенести его на хост до того, как заработает
SSH, нечем — поэтому проще всего отдать его по HTTP. **На виртуалке:**

```bash
make win-setup                                  # напечатает команды и публичный ключ
python3 -m http.server 8000 --directory scripts
```

**На хосте, в PowerShell от администратора:**

```powershell
irm http://192.168.1.6:8000/win-setup.ps1 -OutFile $env:TEMP\win-setup.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File $env:TEMP\win-setup.ps1 `
    -PublicKey "ssh-ed25519 AAAA... core-vm@alex-linux"
```

Ключ `-ExecutionPolicy Bypass` нужен потому, что политика по умолчанию не даёт запускать
никакие `.ps1` вообще. Она не меняется насовсем: ключ действует на один запуск.
Публичный ключ виртуалки печатает `make win-setup` — вставляется он целиком, одной строкой.

Скрипт **идемпотентный**: каждый шаг сначала смотрит, что уже сделано. Запускать повторно
после любой правки безопасно.

Когда вход по ключу проверен — закрыть вход по паролю:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File $env:TEMP\win-setup.ps1 `
    -LockPasswordAuth -SkipInstall
```

**Порядок здесь важен.** Выключить пароль до того, как заработал ключ, — значит остаться
без входа вообще.

## 4. Что скрипт выставляет

| Настройка | Значение | Почему так |
|---|---|---|
| Служба `sshd` | автозапуск, запущена | Иначе после перезагрузки хоста сборка молча недоступна |
| `DefaultShell` | `C:\msys64\usr\bin\bash.exe` | §5 |
| `DefaultShellCommandOption` | `-lc` | Логин-оболочка читает `/etc/profile`, без него `/usr/bin` не в `PATH` и `rsync` не находится |
| `DefaultShellEscapeArguments` | `0` | Экранирование аргументов ломает командную строку `rsync --server` |
| `PubkeyAuthentication` | `yes` | |
| Ключ | `C:\ProgramData\ssh\administrators_authorized_keys` | §5 |
| Профиль сети | `Private` | В профиле `Public` входящее закрыто целиком |
| Правило брандмауэра | порт 22 **только с адреса виртуалки** | Открывать 22 всему миру незачем |
| Каталог | `C:\MyGames\Kolkhoz\core-msvc` | |

Файл `sshd_config` правится на месте, копия сохраняется рядом как `sshd_config.bak`.

## 5. Три подвоха, на которых всё встаёт

**Первый: ключ администратора лежит не там, где ожидается.** Если учётная запись состоит в
группе администраторов, sshd **игнорирует** `C:\Users\<имя>\.ssh\authorized_keys` и читает
общий файл `C:\ProgramData\ssh\administrators_authorized_keys` — и только если права на него
не дают доступа никому, кроме `SYSTEM` и группы администраторов. Лишняя запись в правах — и
ключ отвергается молча, без внятного сообщения.

**Второй: `cmd.exe` не годится как оболочка для sshd.** `rsync` запускает на дальней стороне
`rsync --server ...` и ждёт разбора аргументов по правилам POSIX. Через `cmd.exe` командная
строка искажается, и перенос падает с `protocol version mismatch`, к версиям отношения не
имеющим. Поэтому оболочкой по умолчанию делается bash из MSYS2 — заодно понимающий пути вида
`/c/MyGames/...`.

**Третий: обратная сторона того же решения.** Раз оболочка на хосте — bash, `.bat` вызывается
через `cmd`, а MSYS переписывает всё, что начинается со слэша, в путь Windows. Ключ `/c`
превратился бы в `C:/`, поэтому в [`win-build.sh`](../../scripts/win-build.sh) стоит **`cmd //c`**:
двойной слэш — принятый в MSYS способ сказать «это не путь».

## 6. Проверка с виртуалки

```bash
ssh win 'uname -a; rsync --version | head -1'   # оболочка и rsync на хосте
make sync                                        # только перенос, без сборки
make win                                         # перенос и сборка
```

| Команда | Что делает |
|---|---|
| `make sync` | Перенос `rsync --checksum`, без сборки |
| `make win` | Перенос и сборка Debug |
| `make win-release` | То же, Release |
| `make win-clean` | Снести `build-msvc` на хосте и собрать заново |
| `make win-setup` | Напомнить порядок первичной настройки и показать публичный ключ |

Другой хост или каталог — `make win WIN_HOST=... WIN_DIR=...`.

**Собранная библиотека забирается обратно** в `artifacts/core.lib`; каталог в `.gitignore`.

---

## 7. Почему перенос по содержимому, а не по времени

`rsync` вызывается с ключом **`--checksum`**: отметки времени между виртуалкой и хостом
разъезжаются, и сравнение по ним то пропускает изменённый файл, то гоняет неизменённый.
Ключ `--delete` убирает с хоста то, чего в исходниках больше нет, — иначе удалённый модуль
продолжает собираться там ещё долго.

Из переноса исключены каталоги сборки, `.git/`, `claude/` и `artifacts/`: сборка хоста своя,
остальное на хосте не нужно.

## 8. Если не работает

| Симптом | Причина |
|---|---|
| Хост не пингуется, порт 22 закрыт, но ARP отвечает | Брандмауэр. Профиль сети `Public` либо правило не создано |
| `Permission denied (publickey)` | Ключ не в `administrators_authorized_keys` либо права на файл шире, чем `SYSTEM` + администраторы |
| `protocol version mismatch` при переносе | Оболочкой sshd остался `cmd.exe` или `powershell.exe` |
| `rsync: command not found` | `DefaultShellCommandOption` не `-lc`: без `/etc/profile` в `PATH` нет `/usr/bin` |
| `cmd` жалуется на `C:/c` | Потерялся двойной слэш в `cmd //c` |
| `vswhere not found` | Build Tools не установлены или встали без набора C++ |
| Собралось, а библиотека старая | Инкрементальная сборка. `make win-clean` |
